# CI/CD: сборка образов на GitHub и публикация в Docker Hub

## Как это работает

1. При пуше в ветки `master`/`main` (или создании тега `v*`) GitHub Actions
   автоматически собирает два образа:
   - `itech24/tender-ai-backend` — FastAPI + Celery (worker и beat используют тот же образ)
   - `itech24/tender-ai-frontend` — Next.js
2. Образы пушатся в Docker Hub с тегами:
   - `latest` — последний коммит ветки по умолчанию
   - `sha-<короткий sha>` — конкретный коммит
   - `X.Y.Z` — если создан git-тег `vX.Y.Z`
3. `docker-compose.yml` использует готовые образы из Docker Hub —
   сборка на ноутбуке НЕ нужна, только скачивание готовых образов.

Workflow-файл: `.github/workflows/docker-publish.yml`

## Настройка (один раз)

### 1. Docker Hub: создать Access Token

1. Зайдите на https://hub.docker.com под учёткой **itech24**
2. Account Settings → Personal access tokens → Generate new token
   - Description: `github-actions-tender-ai`
   - Permissions: **Read & Write**
3. Скопируйте токен (показывается один раз)

### 2. GitHub: добавить секреты

В репозитории https://github.com/ShWest37/tender-ai-saas:

Settings → Secrets and variables → Actions → Secrets → New repository secret:

| Имя               | Значение                          |
|-------------------|-----------------------------------|
| DOCKERHUB_USERNAME | itech24                          |
| DOCKERHUB_TOKEN    | токен из шага 1                  |

### 3. GitHub: переменная URL API (необязательно, но важно для прода)

Settings → Secrets and variables → Actions → Variables → New repository variable:

| Имя                | Значение                              |
|--------------------|---------------------------------------|
| NEXT_PUBLIC_API_URL | https://bidflow.ru/api/v1 (для прода) |

`NEXT_PUBLIC_API_URL` вшивается в бандл Next.js **во время сборки образа**.
Если переменная не задана, используется `http://localhost:8000/api/v1`.

## Запуск сборки

- Автоматически: `git push` в `master`/`main`
- Вручную: вкладка Actions → "Build & Push Docker Images" → Run workflow
- Релизная версия: `git tag v1.0.0 && git push origin v1.0.0`

## Запуск проекта (ноутбук / VPS)

```bash
cp .env.example .env      # и заполнить значения
docker compose pull        # скачать свежие образы из Docker Hub
docker compose up -d       # запустить (сборка не нужна!)
```

Или одной командой: `make up`

Откат на конкретный коммит:

```bash
IMAGE_TAG=sha-abc1234 docker compose up -d
```
